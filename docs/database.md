# Database & Schema Architecture (`packages/db`)

ClinIQ uses **PostgreSQL** paired with **Drizzle ORM** (`@cliniq/db`) for strict type safety, zero runtime overhead, and seamless migration workflows.

---

## 1. Entity-Relationship Overview

```
 ┌──────────────────┐
 │  organizations   │◄──────────────┐
 └────────┬─────────┘               │
          │ 1:N                     │ 1:N
          ▼                         │

 │    employers     │      │      roles       │
 └────────┬─────────┘      └────────┬─────────┘

 └──────────────────┘        └──────────────────┘        └──────────────────┘
```

## 2. Table Specifications

### Tenancy & Identity
- **`organizations`**: Root health system or provider group tenancy partition (`id`, `name`, `slug`, `is_production`).
- **`employers`**: B2B employer client groups (`id`, `organization_id`, `name`, `covered_lives`, `pmpm_rate`, `er_cost_per_visit`).
- **`users`**: System accounts (`id`, `organization_id`, `employer_id`, `role`, `email`, `password_hash`, `patient_id`, `provider_id`, `medplum_user_id`, `medplum_practitioner_id`).
- **`roles`**: Customizable granular permissions attached to tenants.

### Clinical Operational Models
- **`providers`**: Clinician profiles with NPI numbers, specialty, and credentials (`id`, `organization_id`, `npi`, `npi_verified`, `role`, `medplum_user_id`, `medplum_practitioner_id`).
- **`nurse_availability`**: Real-time nurse status (`provider_id`, `is_available`, `status`).
- **`patients`**: Patient demographic and risk records (`id`, `organization_id`, `employer_id`, `mrn`, `medplum_patient_id`, `ohs_score`, `risk_tier`, `assigned_nurse_id`).
- **`conditions`**: Diagnoses with ICD-10 codes (`id`, `patient_id`, `icd_code`, `status`).
- **`medications`**: Prescriptions with dosages and refill tracking (`id`, `patient_id`, `name`, `dose`, `prescriber`).
- **`lab_readings`**: Diagnostic values with reference ranges (`id`, `patient_id`, `biomarker`, `value`, `unit`, `interpretation`).
- **`care_gaps`**: Preventive HEDIS quality measure status (`id`, `patient_id`, `measure`, `hedis_code`, `due_date`, `status`).

### Telephony & Realtime AI
- **`call_sessions`**: WebRTC calling sessions (`id`, `caller_id`, `callee_id`, `routing_tier`, `status`, `started_at`, `ended_at`).
- **`call_transcripts`**: Live word buffers generated by Deepgram (`id`, `session_id`, `speaker`, `text`).
- **`maya_conversations`**: Patient chat history with Maya AI clinical RAG (`id`, `patient_id`, `role`, `content`).
- **`fax_inbox`**: Digital fax triage records with OCR classifications (`id`, `sender_number`, `classification`, `confidence`, `matched_patient_id`).

### Financial Accounting & Auditing
- **`financial_event_ledger`**: Transaction-level ER avoidance accounting (`id`, `employer_id`, `patient_id`, `event_type`, `gross_savings`, `net_savings`, `event_date`).
- **`audit_logs`**: Immutable HIPAA PHI access ledger (`id`, `organization_id`, `actor_email`, `actor_role`, `patient_id`, `action`, `resource_type`, `ip_address`, `timestamp`).

## 3. Running Migrations & Seeding

```bash
# Push schema changes to PostgreSQL
pnpm --filter @cliniq/db db:push

# Generate migration SQL files
pnpm --filter @cliniq/db db:generate

# Execute seed script with demo health systems & patients
pnpm run seed
```
